# 亚太—北美机场与航司资料库

机场／航司目录核查日：**2026-10-19**；最新航线／班表核查日：**2026-10-20**。`airports.json`、`airlines.json` 是页面使用的正式资料；`catalog-metadata.json` 分别记录各批次的范围、来源、排除原因和计数。

当前共有194条航司—机场对关系（188条现役／季节性资格、6条待开航计划），以及602条班表记录（146条此前资料、446条当前快照、10条下一季计划）。当前班表最晚适用至2026-10-24，具体有效期以各记录为准。

## 纳入范围

- **亚太区**：大中华区、新加坡、日本、韩国；分类也预留朝鲜，但本次未找到符合条件的朝鲜机场。
- **北美区**：美国本土、阿拉斯加、夏威夷和加拿大。按项目定义不包括墨西哥、关岛、北马里亚纳群岛和其他美国海外属地。
- 至少有一段两区之间的**不停站定期客运**；含季节性服务，排除纯货运、包机及仅代码共享的营销航司。
- 全程经停航班只纳入实际跨太平洋不停站航段的机场。例如 HGH–TAO–YVR 可以证明 TAO，不可以证明 HGH 有不停站航线。

目前收录 **44 座机场**：亚太区 19 座、北美区 25 座。其中 43 座有现役／季节性服务；CTS 属已公布的待开航机场，AC 的 YVR–CTS 服务于 2026-12-17 开始。**26 家独立航司**与 **1 家承运关联公司**分别计数。

## 文件与字段

`airports.json` 保留原表的 `iata_code`、中英文名、城市、国家／地区，增加 ICAO、`region`、经纬度、IANA 时区、`service_status`、`checked_on` 和来源。坐标按机场参考数据定位，不是导航级坐标；中文名称和城市名称由项目统一整理。

`airlines.json` 保留 `iata_code`、`ticket_code`、中英文名、国家／地区与联盟。`ticket_code` 是字符串，以保留前导零；旧表值沿用，新增且未独立核实的票证代码使用 `null`，不猜测。联盟代码：OW=寰宇一家、SA=星空联盟、ST=天合联盟；`null` 表示未列联盟。

每条 `qualifying_service` 只列**一条证明纳入资格的示例航段**，不是完整航线数据库，也不含航班号、频次或时刻。`source_ids` 引用 metadata 中的具体页面，区分官方资料 `primary`、辅助航班索引 `schedule_index` 和机场参考数据 `airport_reference`。部分官方公告早于核查日，不能把 accessed_on 理解为其内容发布时间。现役资格同时参考当前航班索引；不将联程票价格页直接当作不停站证据。

状态：

| 状态 | 含义 |
| --- | --- |
| active | 有现役定期客运服务，不等于每日运营 |
| seasonal | 以季节性定期服务纳入，不保证核查当天有航班 |
| announced | 官方已公布但尚未开航，不计入现役机场 |
| operating_affiliate | 承运关联公司，独立于在售品牌航司计数 |

## 关键修正和边界

- 天府使用 **TFU/ZUTF**；CTU 是双流，旧表把代码和名称配错了。当前名录不把 CTU 作为 TFU 的别名。
- 青岛 **TAO/ZSQD** 对应胶东机场，不再是已关闭的流亭机场。
- 增加 EWR、SZX，原页面的 JFK/EWR 与 HKG/SZX 联合信息卡随之生效。
- Hawaiian 品牌继续存在，但当前代码按 **AS** 记录；旧 **HA** 在 metadata 中注明，避免重复统计同一运营体系。
- **OZ** 在核查日仍单独运营、仍属星空联盟；已公布的 2026-12-16 退出计划单独记录，不能提前改写当前联盟。
- **Air Japan/NQ** 是 ANA 的承运关联公司，单独列明；AirJapan 自有品牌已于 2026-03 停运，不能误说其独立品牌仍销售跨太平洋航线。
- FUK 的历史 HNL 服务已公布暂停；KOA 未核实到核查日现役定期服务，未靠旧网络图或联程售票页纳入。ANC 不能靠货运或包机资格纳入。MFM、PRK 无符合条件的现役服务，因此没有为了凑地域而加入机场。

## 历史资料和页面行为

### 航线扩充（2026-10-19）

`routes.json` 作为地图航线来源，独立于具体航班班表。经10月20日复核，194 条“航司—亚太机场—北美机场”记录中，188 条为现役或季节性资格，覆盖 114 对机场、43 座机场、26 家独立航司；另有 6 条待开航计划，不画成现役连线。季节性航线会显示标记，可能不在核查当天执行。每条记录保存 `source_ids`、`checked_on`、`service_status`，有明确日期时保存 `service_start`／`service_end`。

页面从已收录航线关联班表，优先显示10月20日批次的446条当前记录。此前146条资料仍保留，同方向已有新批次时不重复展示。两条 GUM 记录不在地理范围，另两条原 OZ ICN–HNL 记录不再用于恢复已无现役资格的航线。没有当前班表的航线照常展示承运航司，并标记季节计划或“班表未录入”；不会把一个机场对伪造成一条实际航班。

大陆—美加参考票帝 2026 年 9 月表格，并结合机场／航司来源交叉核实。青岛—温哥华只连接 TAO–YVR，不把杭州始发经停服务画成 HGH–YVR 不停站。川航 TFU–LAX 记录截止 2026-10-24，票帝注明次日起杭州技术经停，后续需要复核。加拿大航空 CTS–YVR、CAN–YVR 与达美 NRT–SEA 的未来计划单独存为 `announced`。ZIPAIR 奥兰多／拉斯维加斯包机、CES 临时加班、仅有代码共享营销资格的航司均未作为定期现役航线扩充。

运行 `python scripts/expand-routes.py` 可重建本轮人工核查快照及新增日航／全日空班表；脚本对自己的导入批次去重，保留原 76 条历史记录。修改航线后同步更新脚本，避免重建时覆盖人工更改。该脚本是已核查事实的可复现导入，不是实时抓取器。来源索引在 `catalog-metadata.json`。

机场筛选每区内多选取并集，两区与航司条件取交集。地图采用太平洋区域视图，以示意弧线连接机场：平均纬度低于35°向下弯，其余向上弯。机场位置不变，绘制、悬停判定与取景使用同一几何。参数集中在 app.js 顶部 ROUTE_CURVE。连线按亚太机场所属地区着色，悬停和选中改用对应深色。曲线不代表实际飞行轨迹。

## 维护与检查

### 航班信息补全（2026-10-20）

新增 **446 条有方向的客运班表记录**，覆盖 26 家航司、185 条航司—机场对关系、112 对机场；每条包含航班号、方向、机型、运营日、来源和核查日期。原 146 条记录逐字段保留，同方向已有新批次时，页面优先显示新批次，避免历史班表重复计数。起降时间按本次要求留空。机型仅能核实到系列时保留系列，不推测具体子型号。

公开索引按具体航司和方向逐页核对，排除货运、代码共享、经停和适用期不覆盖核查日的记录；采用加航官方当前班表，并以长荣、日航、全日空、星宇和 ZIPAIR 官方资料修正索引中的滞后字段。例如 BR08/07 使用 B789，星宇凤凰城使用 A35K，NH181–184 使用 A388。索引原始有效期和机型变体保存在 `source_schedule_variants`，有冲突时官方资料优先。首都航空只录入 JD471/472 的 TAO–YVR 不停站航段。

当前新批次为 `passenger_snapshot_20261020`，最多使用至 2026-10-24，须在冬季航季转换时重新核对。这里的截止日是本次快照的保守复核边界，不代表所有航线于该日停航。部分来源的较早截止日仍保留。机场／航司目录的 2026-10-19 核查日不随班表更新；航线快照的最新核查日为 2026-10-20，各记录保留实际核查日。

另录入 **10 条下一季计划记录**（`seasonal_plans_20261020`）：加航 ICN–YUL 的 2027 年夏季班表，以及 ZIPAIR NRT–SJC 的 2026 年末和 2027 年 3 月分段班表。页面注明“下一运营季计划”，显示航班号、方向、机型及适用期，不计入当前航班数。NH NRT–YVR 的已结束夏季服务仍保留季节性资格，不补造当前班表。

同时纠正三条未来航线：UA NRT–ORD 自 2026-10-25、AA NRT–ORD 自 2027 年 3 月、UA KIX–LAX 自 2027 年 3 月起运营，改为 `announced`。194 条航司—机场对关系中，188 条为现役／季节性资格，6 条为待开航计划；季节性资格不等于核查当天运营。

### 全量复查及日期计算修正（2026-10-20）

对所有 602 条记录逐条检查：446 条当前批次、10 条下一季计划、70 条此前有日期的班表及76条无日期历史资料。历史记录的日期、机型缺口不靠推测补齐；复查报告明确将其列为保留归档，不能等同于当前事实已重新核实。

补充核查证据保存在 `scripts/data/timetable-supplemental-review-20261020.json`。JX9补齐10月24日分段；CI23／CI24部分日期的A359与B77W存在来源分歧，按候选机型显示并提示待核实；MF806周五／周六班期有分歧，保留原索引日期并明确提示。复查通过表示所有记录已处理和分类，不代表这3条分歧已由航司确认。

`operating_periods` 保存每个来源分段的起止日期、运营星期和对应机型；`departures` 是与 `display_from`／`display_to` 相交后，按出发地当地日历逐日生成、去重的出发日期与机型。当前快照窗口从2026-10-20至各条记录有证据的截止日，最晚10月24日。页面统一显示“具体日期范围·期间几班”，不再把星期掩码的数量当成每周班次。未来季节计划保留各自真实适用期。

修正包括：不同星期分段取最早截止日造成的漏班（川航3859/3860周五、华航不同机型分段等）；加航10月24日的相邻官方分段，以及AC9当天由B789改用B77W；补入10月23日加航AC15 YVR–HKG。AC7/AC8在10月20–24日各5班；同一机场对的不同方向不强制班次相等，航季切换时可能另有AC15等独立航班。

`python scripts/research-timetables.py --audit` 独立重新读取此前380个方向的公开来源，并保留10月19–25日相交的来源分段；不覆盖原采集证据。`python scripts/audit-timetables.py` 将每条记录的来源、日历与归档状态写入 `scripts/data/timetable-audit-20261020.json`，遇到未解决的当前来源差异会失败退出。第三方索引无对应页面的BR IAD和JD TAO–YVR由已核对的官方／补充来源支持，不能将HTTP错误当作停航证据。

缓存写入 `artifacts/`；复查证据与逐条结果匹配 `scripts/data/timetable-audit-*.json`，Markdown报告写入 `artifacts/timetable-audit-report.md`。这些均为可删除的本地产物，已由 `.gitignore` 排除。删除后须重新采集复查证据才能再次运行审计；不会影响页面或离线导入。

`world-countries.geojson` 是地图底图，保留 Natural Earth 的全部 177 个国家几何和原始坐标，删除页面未使用的国家属性与集合元数据，并以紧凑 JSON 保存。当前约 249 KB；更新底图时可沿用此方式精简，不必降低边界精度。来源署名保留在地图中。

修改正式 JSON 后运行 `node scripts/validate-data.mjs`。检查代码唯一性、区域、时区和坐标、来源引用、资格航段跨区、待开航日期、联盟和票证格式，以及历史时刻表的关联完整性。

这是人工核查快照，无法保证捕获所有临时停航、后续新增和计划变更。新增机场／航司时必须给出符合范围的航段及来源；新增完整航线／时刻需要另行核实，不能把资格示例自动扩展成完整航班数据。
